# Minecraft Native 남은 개발 계획

메인 메뉴와 게임 중 `Options → Controls → Mouse Settings`에서 0~200% 시점 감도, 마우스 휠 감도, 이산 스크롤, X·Y축 반전을 설정하고 저장합니다. 클릭·드래그와 키보드 조작을 지원하며 데모와 기존 월드의 입력에 적용합니다. 감도 5단계와 양축 반전·합성 이동 2,000개 조합을 설치된 Java 26.3의 실제 마우스 처리와 비교했습니다. 임시 설정 파일을 사용하는 Windows 창에서 메뉴 이동·변경·저장을 확인했고, 게임 일시정지 화면의 마우스·키보드 입력과 적용도 검사했습니다. 설치된 Java 26.3 JAR의 `Options` 바이트코드에서 휠 감도 `0.01~10.0`과 -200~100 로그 범위, 기본 `1.0`, 이산 스크롤의 부호 처리와 감도 곱을 확인했습니다. 301개 로그 슬라이더 값의 입력·표시·저장을 검사했습니다. `ScrollWheelHandler` 결과와 가로·세로·방향 전환을 포함한 523개 입력을 대조했고, 이산 입력과 설정 저장도 합성 시험했습니다. 마우스 휠 설정은 메뉴 목록과 플레이 중 단축바 선택에 반영하며, 바닐라와 같이 반대 방향에서 소수 누적을 초기화합니다. 설치된 26.3 `options.txt`에서 기본 감도 `1.0`과 이산 스크롤 꺼짐을 확인했습니다. 실제 바닐라 메뉴 픽셀 비교, 관전자 휠, 모든 화면 스크롤의 세부 동작은 남아 있습니다. 다른 키 설정, 부드러운 카메라·스코프와 연속 마우스 입력의 전체 바닐라 처리 순서는 아직 미지원입니다.

일반 1인칭 마우스 이동은 Java 26.3 기본 감도 0.5의 계산 순서와 단정밀도 회전 계수를 데모와 기존 월드에 적용합니다. 설치된 Java의 실제 `MouseHandler`와 플레이어 회전에 합성 마우스 입력 100개 조합을 전달해 회전 각도를 비교했습니다. 프레임마다 입력을 모아 처리하는 바닐라의 전체 순서, 스코프와 부드러운 카메라는 아직 지원하거나 비교하지 않았습니다.

시점의 위아래 제한을 Java 26.3의 ±90도에 맞췄습니다. 저장된 시점 복원, 데모·기존 월드의 고정 틱 및 즉시 화면 표시가 같은 제한을 사용하며, 수직에 가까울 때는 플레이어 방향으로 카메라와 경험치 구슬의 기준축을 구성합니다. Java의 `Entity.turn` 제한 코드를 확인했고 합성 세션과 카메라 행렬을 검사했습니다. Windows GPU에서 두 수평 방향의 수직 위·아래 지형 픽셀을 확인했으나 전체 바닐라 화면과 마우스 감도는 아직 비교하지 않았습니다.

메뉴와 게임 중 설정 저장은 다른 버전에서 추가된 알 수 없는 최상위·비디오·사운드 항목을 보존합니다. 기존 파일의 JSON이나 알려진 항목을 읽을 수 없으면 덮어쓰지 않고 오류를 표시합니다. 세 저장 경로에서 합성 설정의 보존과 오류 시 원본 바이트 유지를 검사했습니다. 쓰기 도중 전원 차단에 대한 원자적 교체는 아직 구현하지 않았습니다.

메인 화면의 끊김을 조사하기 위해 이 PC의 1080p 릴리스 테스트를 다시 실행했습니다. DirectX 12·VSync에서 CPU 재그리기 간격 360개의 중앙값은 16.63ms, 99백분위는 21.16ms였고, GPU 스레드의 프레임 완료 수에는 초기화 시간이 포함됩니다. 모니터의 실제 표시 간격은 측정하지 않았으므로 이 결과만으로 사용 중 끊김의 원인이나 해결 여부를 판단할 수 없습니다.

데모와 기존 월드 플레이에서 창 포커스를 잃으면 500ms가 지난 뒤 일시정지 화면을 열고 틱을 멈춥니다. 기존 화면이 열려 있으면 덮지 않으며, 그 사이 포커스를 되찾으면 지연 일시정지를 취소합니다. 설치된 Java 26.3의 포커스 처리와 화면 선택 코드를 확인했고, 합성 시각의 경계·화면 상태와 Windows Vulkan 창에서 전달한 포커스 이벤트 및 틱 정지를 검사했습니다. 바닐라의 `pauseOnLostFocus` 설정 변경과 실제 운영체제 전환에 대한 바닐라 화면 비교는 아직 지원하거나 검증하지 않았습니다.

월드 읽기 도중 차원을 변경하면 이전 차원의 청크·엔티티 지역 파일 캐시를 비웁니다. 같은 지역 좌표를 가진 기본 세 차원과 중첩 경로의 사용자 정의 차원을 합성 월드에서 왕복하며 올바른 파일을 읽고 원본이 유지되는지 검사했습니다. 설치된 26.3 리소스와 합성 저장 월드로 저장된 플레이어 차원·위치와 차원별 청크를 월드 준비 경로에서 확인했습니다. 포털을 통한 게임 내 차원 이동과 실제 바닐라 월드 왕복 저장은 아직 구현하거나 검증하지 않았습니다.

기존 월드 플레이에서 차원에 연결된 `visual/sky_light_factor`와 `visual/sky_light_color` 시간선을 월드 시계로 샘플링해 지형 조명표에 반영합니다. 선형·고정 보간과 덮어쓰기·곱하기 수정자를 지원하며 값이 같으면 조명표 생성과 GPU 업로드를 생략합니다. 설치된 26.3의 기본 낮 시간선에서 709개 시점의 밝기·색을 Java 샘플러와 비교했고, 합성 데이터팩과 Windows Vulkan GPU에서 정오·밤 조명 변화 및 청크 지오메트리 재업로드 생략을 검사했습니다. 바이옴별 조명 속성, 다른 보간·수정자나 시계가 미지원이면 정적 차원 조명을 사용합니다. 하늘 돔·태양·달·날씨, 다른 시간선 속성, 실제 월드의 전체 틱 순서와 바닐라 화면 픽셀 비교는 아직 구현하거나 검증하지 않았습니다.

오버월드형 차원의 단색 하늘 배경은 카메라 주변 216개 바이옴 표본과 차원의 `visual/sky_color` 시간선을 적용하고 틱 사이를 보간합니다. 바이옴이나 시계가 준비되지 않은 경우에는 이전 색 또는 기본 배경을 유지합니다. 합성 바이옴과 설치된 26.3의 낮 시간선에 대해 위치·시간 44개 조합을 Java의 가중 표본 및 시간선 계산과 비교했으며, Windows Vulkan GPU에서 색 공간 변환과 배경 변경 시 지형 지오메트리가 재업로드되지 않는 것을 검사했습니다. 실제 월드 화면과 바닐라의 픽셀 비교, 하늘 돔과 엔드 하늘은 아직 남아 있습니다.

하늘이 없는 차원에서는 `visual/fog_color`를 같은 바이옴 표본과 해당 차원 시간선으로 계산해 단색 배경의 기초 색으로 사용합니다. 설치된 네더 황무지·영혼 모래 골짜기의 안개색을 읽고, 합성 바이옴 44개 위치·시간 조합의 색 혼합을 Java 26.3과 비교했습니다. 날씨·효과를 반영한 최종 바닐라 안개색은 아직 아니며 실제 네더 화면 비교도 아직 하지 않았습니다.

하늘이 없는 차원의 안개 시작·끝 거리는 차원 속성, 주변 바이옴과 지원되는 시간선을 함께 계산해 지형 셰이더에 반영하고 틱 사이를 보간합니다. 덮어쓰기·덧셈·뺄셈·곱셈·최소·최대 수정자와 선형·고정 시간선 보간을 지원하며 미지원 값은 지형 안개를 보류합니다. 같은 바이옴 표본을 배경색과 공유하고 카메라에서 정점까지의 구형 거리로 지형 색을 배경색에 섞습니다. 합성 바이옴·시간선과 Java 26.3 계산을 비교했으며 Windows Vulkan GPU에서 안개 활성·해제와 지형 업로드 생략을 검사했습니다. 렌더 거리 안개, 시야·날씨·상태 효과 및 실제 바닐라 화면·성능 비교는 아직 남아 있습니다.

하늘이 없는 차원의 안개색은 차원·바이옴·시간선에서 읽은 하늘색과 `visual/sky_fog_end_distance`를 이용해 시야 거리에 따라 섞습니다. 이 구현은 현재 청크 로딩 반경을 시야 거리로 사용하고 Java의 최소값 2청크를 적용합니다. 합성 색상과 거리 20개 조합을 Java 26.3의 보간 함수와 비교했습니다. 안개색의 일출·일몰 방향, 날씨와 상태 효과 보정, 실제 바닐라 화면 비교 및 바닐라와 동일한 시야 거리 처리는 아직 남아 있습니다.

비디오 설정에서 2~32청크의 렌더 거리를 고르고 저장하며, 기존 월드 플레이 중에도 로딩 반경을 바꿀 수 있습니다. 기본값은 12이고, 초기 준비는 인접 청크부터 진행한 뒤 백그라운드로 나머지를 읽습니다. 변경은 26.3의 슬라이더처럼 600ms 지연하며 화면을 떠날 때 보류된 값을 반영합니다. Java 슬라이더 입력 값과 합성 세션의 반경 확대·축소·재진입을 검사했습니다. 아직 저장되지 않은 청크의 생성과 바닐라와 같은 정확한 렌더·시뮬레이션 거리 구분, 12청크 실제 월드 성능 비교는 남아 있습니다.

청크 요청에서는 이미 정착한 청크와 없는 청크의 목록 앞부분을 반복 확인하지 않습니다. 로딩 범위가 바뀌거나 엔티티 재시도가 도래하면 원래 순서로 다시 검사하며, 아직 처리 중인 청크는 앞부분에서 제외하지 않습니다. 13×13 합성 청크의 로딩 순서가 기존 가까운 순서와 같은지 비교하고 최소 1,000번의 중복 확인이 생략되는 것을 검사했습니다. 실제 월드의 프레임 시간이나 바닐라 대비 성능은 아직 측정하지 않았습니다.

전체 월드 메시의 고정 600만 정점 제한을 없애고 개별 청크 제한을 유지합니다. 불투명 지형은 청크별 GPU 버퍼를 사용하며, 반투명 지형의 합산 버퍼는 생성 전에 정수 오버플로와 GPU 최대 버퍼 크기를 확인합니다. 공유 메시를 사용한 625청크 합성 회귀 시험에서 총 625만 정점의 증분 장면 구성을 검사했습니다. 이는 625만 개의 실제 지형 정점을 GPU에 업로드하거나 12청크 실월드의 메모리·성능을 측정한 시험은 아닙니다.

청크가 사라져 마지막으로 사용하던 블록 상태나 바이옴이 빠져도 준비한 리소스를 잠시 유지해 아틀라스와 나머지 메시의 전체 재생성을 피합니다. 레지스트리 값이 바뀌면 다시 준비하고, 보관량이 커지거나 보관된 텍스처가 맞지 않으면 현재 청크에서 필요한 리소스로 재구성합니다. 합성 세션의 청크 제거·복원·레지스트리 교체와 리소스 실패 후 재구성을 검사했으며, 26.3 리소스를 사용한 Vulkan 창에서 마지막 흙 블록을 제거했을 때 아틀라스 재업로드 없이 변경 청크 하나만 업로드되는 것을 확인했습니다. 새로운 리소스가 추가되는 경우의 전체 아틀라스·메시 재생성과 실제 월드 프레임 시간 비교는 아직 남아 있습니다.

기존 월드 지형 메시에는 밝기가 곱해진 색 대신 블록빛·하늘빛 인덱스를 보관하고, 256개 RGB 조명표를 GPU 정점 단계에서 적용합니다. 조명표만 바뀌면 4 KiB 버퍼를 갱신하며 청크 지오메트리와 아틀라스를 다시 업로드하지 않습니다. 정점 하나는 36바이트에서 40바이트로 증가합니다. 떨어진 아이템은 지원되는 일반 모델에 설치본 또는 리소스팩의 텍스처와 `ground` 변환, 인챈트 광택을 사용합니다. 수량별 1–5개 모델과 평면·입체 배치, 위치 보간, 부유·회전은 바닐라의 방법을 따릅니다. 모델과 텍스처를 GPU에 캐시하고 같은 모델의 복사본을 인스턴스로 묶으며, 계속 보이는 모델은 유휴 캐시 한도를 넘더라도 매 프레임 다시 업로드하지 않으며, 서로 다른 70개 모델의 GPU 리소스 재사용을 확인했습니다. 같은 시드를 직접 제공했을 때 복사본 배치 324개 조건과 전체 변환 144개 조건을 Java 26.3의 실제 렌더러와 대조했고, 합성 GPU 시험에서 일반 모델과 광택 모델을 확인했고, 설치된 다이아몬드 검 모델도 실제 GPU에 렌더링했고, 게임 UI의 비동기 로딩과 광택 활성·해제를 Windows GPU 창에서 확인했습니다. 이 PC의 릴리스 CPU 측정에서 1,000개 아이템의 3,000개 인스턴스 변환은 중앙값 0.057ms, p95 0.142ms였으며 모델 로딩·GPU 전송·화면 표시는 포함하지 않습니다. 검증된 설치 JAR의 아이템 등록 순서와 색상·구리 묶음을 백그라운드에서 해석해 숫자 ID를 얻고, 손상도를 더해 복사본 배치 시드로 사용합니다. 아이템 1,658종의 ID 전체와 돌·다이아몬드 검·철 투구의 손상도 및 사용자 최대 손상도 30개 조합을 설치된 Java와 비교했으며 리소스팩은 이 정보를 덮어쓸 수 없습니다. 검증된 JAR을 연 뒤 등록 정보를 재구성하는 비용은 이 PC의 릴리스 측정에서 중앙값 2.125ms, p95 4.415ms였고 모델 로딩 스레드에서 한 번 수행합니다. 해석할 수 없는 등록 형식이나 알 수 없는 아이템은 근사 시드를 사용하며, 엔티티별 부유 위상도 실제 월드 난수를 복원하지 않습니다. 지원하지 않는 아이템 모델은 임시 큐브로 남고, 정확한 조명·그림자·반투명 렌더 레이어, 애니메이션 텍스처, 특수 광택과 바닐라 화면 비교도 남아 있습니다. 저장된 아이템의 기본 복원은 지원하지만 실제 월드 저장은 아직 지원하지 않습니다.

저장된 엔티티 청크에서 아이템의 UUID, 위치·속도, 중력 상태, 수명·획득 지연·체력, 소유자·투척자와 아이템 구성 요소를 읽는 API를 추가했습니다. 청크가 없거나 읽을 수 없는 상태를 빈 청크와 구분하고, 같은 청크의 중복 아이템 UUID와 손상된 데이터는 오류로 보고하며 원본 NBT와 알 수 없는 필드는 보존합니다. Java 26.3 ItemEntity가 실제로 읽는 7가지 숫자·형식의 수명과 지연 및 체력, 아이템 내구도와 소유자를 Java가 기록한 NBT로 비교했습니다. 기본 아이템을 세션에 생성하고 청크 퇴거 시 메모리에 보관하며 재진입 시 중복 및 획득 후 부활을 막는 합성 시험을 통과했습니다. 중복 UUID와 손상된 청크는 오류로 보고합니다. 아이템 저장 및 전체 화재 피해 등은 지원하지 않으며 모든 청크 이탈 상태를 세션 동안 메모리에 유지합니다.

아이템 시뮬레이션에서 렌더링 틱과 소멸 수명을 분리하고 무한 수명·획득 지연 및 중력 비활성 상태를 표현할 수 있게 했습니다. 제어된 공기·평지 환경에서 무한 및 음수 수명, 무한·음수·일반 획득 지연, 중력 설정을 포함한 32개 초기 상태의 1,280틱을 Java 26.3 ItemEntity의 위치·속도·접지·수명·지연과 비교했습니다. 플레이어 획득·청크 이동을 포함한 전체 동작은 아직 Java와 비교하지 않았습니다.

싱글플레이어 UUID를 월드에서 세션으로 전달하고 소유자가 지정된 아이템은 UUID가 일치할 때만 획득하도록 준비했습니다. Java 26.3의 획득 조건을 확인하고 합성 시험을 추가했지만 실제 플레이어를 사용한 Java 비교는 남아 있습니다.

아이템 병합의 묶음 크기 조건을 Java 26.3과 4,096개 수량 조합으로 비교하고, 아이템과 구성 요소가 다르면 병합하지 않는 검사를 추가했습니다. 기본 병합 주기·범위·소유자·수명과 엔티티 제거를 시뮬레이션에 연결하고 합성 테스트를 추가했습니다. 같은 소유자와 구성 요소를 가진 두 엔티티의 수량 3,969개 조합에서 생존 엔티티와 수량·수명·획득 지연을 Java와 직접 비교했습니다. 세 엔티티의 수량 125개 조합도 같은 이웃 순서를 제공해 Java 병합 메서드와 비교했습니다. 실제 Java 엔티티 섹션 저장소에서 원점의 8개 섹션에 걸친 조회 순서를 비교하고 해당 섹션 순서를 병합에 적용했습니다. 엔티티가 섹션을 이동할 때 새 삽입 순번을 부여하고 Java 저장소의 제거·재삽입 순서와 비교했습니다. 청크 재활성화 시 기존 순서를 유지해 새 순번을 부여하고 저장 수명은 유지하면서 저장되지 않는 틱 수를 초기화합니다. 실제 Java 월드의 퇴거·복원 왕복은 아직 비교하지 않았으며, 512개 이상의 아이템은 필요할 때 공간 인덱스를 만들고 이동 중 갱신하며, 밀집된 경우 전체 검색으로 돌아갑니다. 후보는 기존 엔티티 순서로 정렬합니다. 섹션 순서 적용 전 이 PC의 릴리스 합성 측정에서 흩어진 1,024개 아이템의 80틱 중앙값은 전체 검색 5.474ms, 개선 후 3.038ms였고 밀집한 경우는 각각 11.977ms와 11.999ms였습니다. 실제 월드 성능은 아직 측정하지 않았습니다.

엔티티 청크 읽기가 실패한 경우 백그라운드에서 재시도하고 성공한 데이터는 이미 로드된 블록을 바꾸지 않고 세션에 반영합니다. 반복 실패의 재시도 간격은 5초부터 최대 80초까지 늘리며, 범위를 벗어난 청크의 재시도는 취소합니다. 재시도는 엔티티 청크만 읽으므로 블록 디코딩과 높이맵 계산을 반복하지 않습니다.

## 1. 월드 데이터와 렌더링

- 돌 버튼 설치는 클릭한 짧은 풀·양치식물·마른 덤불·불을 직접 교체하거나 인접한 같은 블록과 일반 물·용암을 교체할 수 있다. 클릭한 칸을 교체할 때와 인접 칸에 설치할 때 Java의 후보 방향 순서를 각각 적용하며 10,920개 시선·지지 조합과 교체 판정을 비교했다. 합성 세션에서 실제 풀 클릭 및 인접 식물·유체 교체를 검사했다. 다른 교체 가능 블록과 사용자 정의 동작은 아직 처리하지 않는다.
- 돌 버튼의 부착 판정에 구현된 완전 블록과 반 블록·계단의 지지 면을 적용한다. 지지 블록이 이들 상태로 바뀌었을 때도 해당 면이 지지력을 잃으면 버튼이 떨어진다. Java 26.3의 블록 상태 58,512개 면과 합성 세션의 반 블록·계단 설치 및 지지 변경을 비교했다. 클릭한 면에 부착할 수 없으면 시선 순서에 따라 다른 지지 면을 검사하며, Java의 방향 순서와 대체 설치 5,460개 사례 및 미해석 지지 블록 보류를 검사했다. 미지원 블록의 지지력은 아직 남아 있다.
- 기존 월드에서 돌 버튼을 직접 채굴하면 일반 도구에 따른 진행도와 내구도 소모를 적용하고 활성 데이터팩 전리품을 사용한다. 빈손과 35개 일반 도구에 대한 Java 26.3 비교와 합성 세션의 빈손·곡괭이·크리에이티브 파괴를 검사했다. 인챈트와 사용자 데이터팩의 채굴 태그 변경은 아직 반영하지 않는다.
- 기존 월드의 버튼은 눌림 상태와 바닥·벽·천장 방향에 따른 선택 형상을 사용하고 플레이어 충돌을 막지 않는다. 설치된 Java 26.3의 버튼 상태 360개와 광선 표본, 합성 세션의 조준을 비교했다. 돌 버튼은 확인된 완전한 블록 면에 주 손 또는 보조 손으로 설치할 수 있다. 돌 면의 여섯 방향과 시선 13개씩을 Java 설치 코드와 비교하고 게임 모드별 수량을 합성 세션에서 검사했다. 돌 버튼을 누르면 20틱 동안 켜지며 저장된 버튼 예약 틱도 불러온다. Java의 버튼 지속 시간을 확인하고 합성 세션에서 중복 누름과 청크 언로드·재로드를 검사했다. 지지 블록이 공기로 바뀌면 버튼을 제거하고 활성 데이터팩의 전리품과 블록 드롭 규칙을 적용한다. 여섯 부착 방향과 주변 블록 변경을 Java의 상태 갱신과 비교했고, 합성 데이터팩·드롭 규칙과 설치된 기본 전리품을 검사했다. 지지가 공기가 아닌 다른 블록으로 바뀌는 경우의 전체 판정, 버튼과 다른 종류의 블록 틱 간 순서, 저장 초안의 버튼 틱 기록, 미지원 지지 블록의 처리, 레드스톤 전달은 아직 구현하지 않았다.
- 26.3의 차원별 청크, 블록 상태, 바이옴, 조명, 플레이어와 원본 NBT를 손실 없이 읽는다. 생성되지 않은 청크와 데이터가 없는 섹션을 구별한다.
- 블록 상태 식별자와 속성을 런타임 레지스트리에 연결하고, 모델 상속·변형·다중 파트·텍스처를 실제 메시 생성에 사용한다. 사용자 리소스팩의 우선순위도 동일하게 적용한다.
- 섹션 경계 면 제거와 청크별 증분 메시, 비동기 청크 생성, 불투명·컷아웃·반투명 레이어, 하늘·블록 조명과 주변광을 완성한다. 기존 청크 읽기는 플레이 모드에서 비동기로 동작한다. 바닐라 월드는 쓰기 기능이 검증될 때까지 읽기 전용으로 연다.
- 완료 조건: 복사한 26.3 월드의 세 차원에서 대표 지형과 모델을 렌더링하고, 동일한 시점의 바닐라 화면 및 블록·바이옴·조명 데이터와 비교한다.

## 2. 안전한 저장과 데이터팩

- Windows의 단일 청크 쓰기 경로를 추가했다. 블록 상태 초안은 높이맵을 다시 계산하고 게임 레지스트리가 모든 변경을 승인해야 저장할 수 있으며, 파일의 원본 청크 NBT가 초안 생성 시점과 다르면 거부한다. Anvil 지역 파일의 백업·검증된 임시 교체와 수정 청크 타임스탬프를 적용하고, 나머지 지역 레코드와 외부 청크 파일은 보존한다. 높이맵 누락·레지스트리 거부·오래된 초안에서 원본이 그대로 남는 것과 알 수 없는 태그 보존을 검사했다. 합성 저장 결과를 설치된 Java 26.3이 다시 읽어 블록 상태와 높이맵을 확인했다. 이 기반은 게임 세션에서 아직 호출하지 않는다. 조명·블록 엔티티·주변 갱신·POI 등 모든 부수 효과를 검증하고, 여러 청크·플레이어·월드 파일을 하나의 저장으로 조정하기 전까지 기존 월드는 계속 읽기 전용이다.
- `WorldSavePlan`은 여러 차원·지역의 청크 초안, 선택한 플레이어 데이터와 차원 시계 파일을 먼저 검증한 뒤 한 복구 가능 트랜잭션으로 교체한다. 기존 지역·외부 청크·플레이어·시계 파일을 백업하며, 원본이 초안과 일치하고 스테이징 결과를 다시 읽을 수 있을 때만 교체한다. 합성 검사에서 두 지역의 세 청크, 플레이어 위치와 차원 시계 파일을 함께 저장했고, 알 수 없는 플레이어·시계 NBT 필드와 기존 gzip 압축을 보존했다. 오래된 시계 원본은 교체 전에 거부한다. Java 26.3 읽기 검증은 계획 API로 저장한 단일 청크에 통과했다. 레벨·POI·전체 엔티티 파일과 모든 게임 부수 효과는 미포함이므로 아직 게임 저장에 연결되지 않았다.
- 로드된 월드 스냅샷이 블록의 원본·최종 상태를 위치별로 기록한다. 원본으로 되돌린 편집은 저널에서 제거하고, 청크가 퇴거된 동안에도 편집을 유지해 재로딩 시 복원한다. 재로딩 원본이 원래 상태나 이미 기록된 최종 상태와 다르면 청크 가져오기를 거부한다. 복사본의 저널 격리, 음수 좌표, 청크 퇴거·복원과 오래된 원본 거부를 검사했다. 이 기록은 아직 저장되지 않는다.
- 세션은 변경 블록, 데이터팩 기반 높이맵, 지원되는 모래·자갈·돌 버튼 틱과 물·용암 틱을 한 청크 초안으로 모은다. 저장된 버튼과 낙하 블록 틱의 원래 하위 틱 순서를 함께 복원하고 새 일정에는 공유 순번을 사용한다. 모래·자갈과 버튼은 이제 같은 due-order 실행 루프와 틱당 65,536개 처리 한도를 공유하며, 누락된 청크의 이벤트는 복원 버전이 바뀔 때까지 대기한다. 합성 검사에서 공동 처리 한도를 확인했고, 저장 틱의 순서와 지연을 Java 26.3 `SavedTick` 코덱과 비교했다. Java 26.3 `LevelChunkTicks` 양방향 입력 순서도 확인하고, 돌 버튼이 모래에 지지된 합성 월드에서 실행 결과가 순서에 따라 달라지는 시나리오를 세션에 추가했다. 전체 `ServerLevel` 월드의 틱 실행은 아직 직접 차등 비교하지 않았다. 예약·실행·대기 지연 변경이 발생한 틱 전용 청크도 변경 목록에 포함하고, 저장 전 청크 퇴거를 막는다. 조명·블록 엔티티·POI 및 기타 부수 효과는 미포함이며 파일 저장에는 아직 연결하지 않았다.
- 다음으로 세션 변경 기록을 엔티티·플레이어·월드 설정까지 확장하고, 블록 상호작용의 조명·블록 엔티티·주변 갱신·POI 등 미포함 부수 효과를 같은 저장 초안으로 모은다. 각 초안의 검증 결과를 멀티파일 `WorldSavePlan`과 연결하고, 대상 파일의 백업·원본 해시 대조·복구가 확인된 뒤 게임의 저장·나가기 UI를 연결한다.
- 기존 아이템과 낙하 블록이 섞인 엔티티 청크의 변경을 하나의 메모리 초안으로 합친다. 원본에 없는 아이템의 생성, 제거·획득, 다른 청크로의 이동 및 중복 UUID는 거부한다. 합성 세션과 Java 26.3으로 작성 결과를 읽는 검사를 통과했다. 이 초안은 미지원 엔티티의 시뮬레이션과 여러 청크·플레이어·블록 변경의 일관성을 보장하지 않으므로 파일 저장에 연결하지 않는다.
- 저장된 아이템 엔티티의 위치·속도·수명·획득 지연·피해 상태와 수량을 원본 NBT에 반영하는 메모리 초안을 추가했다. 아이템 구성 요소와 미해석 태그를 유지하고 중복 필드, 지원하지 않는 형식과 소유자 변경 등을 거부한다. 합성 세션과 Java 26.3의 대표 아이템 NBT 읽기를 검사했다. 회수·합치기·신규 엔티티·청크 간 이동을 다른 저장 데이터와 함께 조정하는 작업은 남아 있다.
- 저장된 낙하 엔티티의 변경은 기존 엔티티 청크의 메모리 초안에 합칠 수 있다. 다른 엔티티와 알 수 없는 태그를 유지하며 UUID 중복, 원본 변경, 엔티티 생성·삭제와 청크 간 이동을 거부한다. 합성 세션 검사와 Java 26.3의 초안 NBT 읽기를 통과했다. 다른 엔티티와 청크 간 변경의 일관성을 아직 처리하지 않으므로 실제 저장에는 연결하지 않는다.
- 청크·엔티티·POI·플레이어·월드 설정을 보존하며 26.3 구조로 다시 저장한다. 알려지지 않은 태그는 보존하고, 보존할 수 없는 데이터나 지원하지 않는 기능이 있으면 쓰기를 거부한다. 플레이어 인벤토리·장비·제작법 책에 대한 메모리 초안은 원본의 다른 태그를 유지하며 대표 아이템과 제작법 책을 Java 26.3 코덱에서 다시 읽었다. 플레이어 위치와 다른 상태, 파일 쓰기 및 월드 전체의 일관성 검증은 아직 남아 있다.
- 쓰기 전 백업과 임시 파일·교체 절차를 마련하고, 중단·오류 후 복구를 검증한다. 월드 변환은 원본을 변경하지 않는 복사본에서 검증한다.
- 표준 데이터팩의 등록 정보, 태그, 제작법, 전리품, 함수·명령어, 월드 생성 및 차원 설정을 단계적으로 처리한다. 구버전 월드 변환은 26.3 저장 왕복이 완료된 뒤 다룬다.
- 완료 조건: 바닐라와 구현체에서 월드 복사본을 번갈아 열고 수정·재개해 상태가 유지되며, 데이터팩 대표 사례도 같은 결과를 낸다.

## 3. 월드 생성과 시뮬레이션

- Java 난수·수학 동작을 기준으로 노이즈, 밀도 함수, 바이옴, 동굴, 지형 특징과 구조물을 구현한다. 26.3 밀도 함수의 단정밀도 중간 계산과 작업 순서를 보존한다.
