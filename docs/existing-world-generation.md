# 기존 월드의 미생성 청크

기존 월드에서 이동할 때 필요한 청크를 생성하려면 저장된 생성 설정과 데이터팩,
이웃 청크, 실행 중인 월드 상태를 같은 시점의 입력으로 다뤄야 한다. 현재 구현은
이 경로의 중간 단계이며 플레이 화면이나 실제 월드 쓰기에 연결되지 않았다.

`biomes` 단계의 빈 청크는 캡처된 3×3 바이옴과 구조물 시작점·참조를 이용해
지형, 표면과 동굴을 계산할 수 있다. 생성기에 연결된 데이터팩 스냅샷의 블록
레지스트리와 동굴 설정은 재사용한다. 기존 블록이나 미처리 틱이 있거나 블렌딩·
지하 재생성이 필요한 청크는 계산을 중단한다. 결과는 `terrain` 단계의 중간
데이터로, 월드 파일을 변경하지 않는다.

구조물 생성이 켜진 월드에서도 캡처할 때 지형이 없던 청크의 구조물 시작점을
같은 시드와 데이터팩으로 준비한다. 다중 조각과 경계, 생성 순서를 보존하고,
이웃에 저장된 시작점과 합쳐 구조물 참조와 지형 보정을 계산한다. 준비 도중
취소하거나 지원하지 않는 구조물이 나오면 작업을 중단한다. 기존 프로토 청크가
구조물 시작 단계에 도달하기 전인 경우와 새 시작점의 장식·저장은 아직 지원하지
않으므로 실제 청크를 저장하지 않는다. 설치된 26.3 리소스와 합성 데이터팩으로
생성 결과를 기존 신규 월드 생성 경로와 비교했으며, 해당 경로의 바닐라 전체
월드 호환성이 확인된 것은 아니다.

계산한 지형은 같은 캡처의 바이옴과 블록 레지스트리로 청크 형식으로 변환한다.
원래 청크 문서와 후처리 기록을 보존하며, 동일 캡처에서 나온 청크만 하나의
지형 작업에 모을 수 있다. 서로 다른 캡처 또는 중복 청크는 거부한다.
생성한 블록 팔레트만 원본 섹션에 결합한 부분 NBT 초안도 만들 수 있다.
원본 바이옴과 알 수 없는 태그, 구조물 정보를 보존하고 원본이 바뀌었는지
확인한다. 같은 생성 결과의 `WORLD_SURFACE_WG`, `OCEAN_FLOOR_WG`와 순서가
있는 후처리 표시를 부분 초안에 추가할 수 있다. 이미 기록된 높이맵이나
미처리 표시가 있으면 안전하게 합칠 수 있을 때까지 중단한다. 상태와 나머지
데이터는 아직 완성되지 않아 저장할 수 없다.

합성한 `biomes` 단계 입력에서 세 차원의 지형 초안을 생성한 뒤, 임시 사본의
상태만 `terrain`으로 바꾸어 설치된 Java 26.3의 청크 직렬화 코드로 읽고 다시
쓰는 테스트가 있다. 블록 상태와 바이옴, 두 월드 생성 높이맵, 후처리 표시,
구조물 정보 및 빈 틱 목록을 비교한다. 이는 실제 월드의 생성·저장이나 재접속
호환성을 검증한 것은 아니다.

다음 장식 단계에 필요한 기능 목록은 캡처된 3×3 저장 바이옴과 같은 데이터팩의
전역 기능 순서에서 선택할 수 있다. 전역 순서는 같은 생성기에서 재사용하며,
다른 캡처의 생성기와 계획을 혼합하거나 이웃이 빠진 경우는 거부한다. 선택된
기능과 필요한 블록·태그는 같은 데이터팩에서 배치 준비 단계까지 해석할 수 있다.
지원하지 않는 기능은 지형을 변경하기 전에 중단한다. 구조물 생성이 꺼졌거나
저장된 구조물 참조가 없는 청크는 같은 캡처에서 복원한 주변 지형과 준비된
스케줄러를 이용해 지원하는 기능을 중간 지형에 배치할 수 있다. 저장된 매장된
보물 참조는 원래의 구조물·참조 순서로 배치하며, 바뀐 경계와 원본 시작점은
같은 생성 작업에서 보존한다. 보존한 원본 청크에 변경된 보물 경계만 반영하는
부분 NBT 초안도 만들 수 있으며, 시작점·참조 수가 캡처한 데이터와 다르면
중단한다. 지원하지 않는 참조나 해석 중 버려지는 데이터가
있으면 중단한다. 별도로 출처와 시점을 확인한 초기 조명 스냅샷을 전달하면 밝기
정보가 필요한 지원 기능도 실행할 수 있다. 스냅샷은 같은 차원의 채널과 현재 중간
지형 시점에 묶이며 지형이 바뀌면 만료된다. 호출자는 조명 엔진에 청크가 등록되거나
빛이 전파되지 않았고 배치 중 표시 조명이 바뀌지 않는 상태와 스냅샷의 출처를 직접
확인해야 한다. 저장된 조명이나
실행 중인 월드의 조명을 자동으로 복원하는 기능과 다른 구조물의 배치는 아직 없다.
배치가 성공한 영역의 이전 지형 초안은 재사용하지 않는다. 이 중간 결과는
아직 플레이 세션이나 실제 월드 저장에 연결되지 않았다.

기능 배치가 닿은 청크는 현재 시점의 블록, 높이맵, 후처리 표시, 블록 엔티티,
틱, 기록된 생성 엔티티와 지원되는 보물 시작점 변경을 부분 NBT 초안으로 묶을 수 있다.
기존 프로토 청크 엔티티 뒤에 기록된 생성 엔티티를 순서대로 추가하며, 별도 엔티티
리전의 원본은 수정하지 않고 함께 보존한다. 생성 엔티티의 전체 수집 여부와 나중의
엔티티 리전 병합은 아직 검증되지 않았다.
기능 초안은 같은 데이터팩에서 분류한 배치 기능에 대해 제한된 근거를 포함한다.
주변 3×3 기능 단계가 끝나고 지금까지 실행한 모든 배치 기능이 엔티티를 생성하지
않는 것으로 확인된 경우에만 이 범위가 확인된 것으로 표시한다. 알 수 없는 기능은
확인을 무효화한다. 이 표시는 구조물, 기존 엔티티, 몹 생성이나 최종 저장의 완전성을
뜻하지 않는다.
원본 바이옴과 알 수 없는 태그를 유지하고, 기존 조명이 있는 입력은 중단한다.
이웃 청크 추가나 후속 기능 배치가 성공하면 이전 초안의 시점 검증이 실패한다.
엔티티 측면 데이터의 최종 병합과 이후 생성·조명 단계는 포함하지 않으므로 저장
가능한 청크로 취급하지 않는다.

저장된 조명이 없는 재개 지형에는 별도의 빈 조명 추적기를 만들어
`INITIALIZE_LIGHT`를 실행할 수 있다. 호출자는 주변의 기존 조명이나 라이브 엔진이
영향을 주지 않는 상황인지 확인해야 한다. 실제로 완료한 기능 단계만 등록하며,
전파 전에는 주변 3×3 청크가 같은 추적기에 등록됐는지 검사한다. 지형이 바뀌면
추적기와 전파 엔진은 만료된다. 전파 결과는 메모리상의 조명 스냅샷이며 저장된 조명
복원이나 청크 저장을 뜻하지 않는다. 전파된 청크의 부분 초안에는 해당 시점에 할당된
조명 레이어를 추가할 수 있다. 기존 섹션의 바이옴과 알 수 없는 필드는 유지하고,
원본 조명이 있거나 조명 컬럼이 없거나 범위 밖 레이어가 있으면 중단한다. 후속 전파나 지형 변경은
초안의 시점 검증을 무효화한다. 청크 상태와 엔티티·저장 의존성은 확정하지 않는다.

생성기에서 몹 생성을 끄거나 현재 `spawn_mobs` 규칙이 꺼진 경우에는 조명이 끝난
청크의 `SPAWN` 단계를 진행할 수 있다. 호출자는 규칙을 같은 월드 세션에서 읽고
라이브 변경과 저장 전 원본을 별도로 확인해야 한다. 이 단계는 기존 프로토 엔티티와
기록된 기능 엔티티를 그대로 유지한다. 일반적인 몹 생성 경로와 전체 엔티티 수집,
`FULL` 전환 및 저장은 아직 연결되지 않았다.

몹 생성이 켜진 경우에는 캡처된 바이옴, 차원·데이터팩 속성, 호출자가 제공한 시계와
월드 시드를 이용해 Java의 생성 후보를 순서대로 계산한다. 지원하는 동물 후보는 재개
지형의 높이·월드 경계·블록 충돌·밝기와 생성 규칙을 검사한다. 거부된 후보는 Java의
난수 순서에 따라 다음 후보로 진행하며, 모든 후보가 거부되거나 후보가 없으면 엔티티를
추가하지 않고 `SPAWN`을 완료한다. 통과한 양·말·당나귀·돼지·소·닭은 독립 UUID를
받아 개체별 규칙과 액체 장애물을 검사하고, 원래 프로토 엔티티 뒤에 초기화된 NBT를
추가할 수 있다. 돼지·소·닭의 변종은 활성 데이터팩의 바이옴·달·구조물 조건을
사용하며, 닭의 알 간격은 독립 개체 난수에서 제공받는다. UUID의 월드 전체 중복,
시계·규칙·월드 경계와 라이브 월드 변경은 별도 확인이 필요하다. 다른 동물의 초기화와
실제 월드 저장·플레이 연결은 아직 지원하지 않는다.

이후에는 생성 결과와 원본 청크의 구조물·틱 등 나머지 데이터를 결합하고,
주변 의존 청크의 각 생성 단계를 이어서 실행해야 한다. 실제 세션에 반영하기
전에는 라이브 청크 변경, 블록 엔티티·엔티티·POI, 데이터팩과 디스크 원본을
검증해야 한다. 저장은 검증된 변경을 같은 트랜잭션에 넣고 백업과 중단 복구를
보장한 뒤에만 연결한다. 26.3 복사 월드와 Java 양쪽에서 생성 경계 및 플레이 후
재접속 결과를 비교하는 검증도 필요하다.

실행 중 청크 생성에서 계단·울타리·발광 이끼 갱신이 아직 없는 청크를 기다릴
때는 해당 대기열을 그대로 보존한 채 생성 입력을 캡처할 수 있다. 대기열의 내용이나
순서가 바뀌거나, 다른 청크가 도착해 이미 갱신을 실행할 수 있게 되면 생성 결과를
다시 검증해야 한다. 최종 반영용 검증은 미저장 지형, 미처리 조명, 스트리밍 입력 및
알 수 없는 블록 갱신을 여전히 거부한다. 대기 중인 울타리는 청크가 도착한 뒤 기존
세션 처리 순서로 재실행되는 합성 사례를 검사한다.

남은 연결 작업은 생성 결과의 청크·엔티티·POI와 변경된 이웃을 한 번에 반영하고,
대기 갱신을 이어 실행하는 것이다. 플레이 중 바뀌는 시간과 예약 틱 순서, 미저장
이웃 지형과 생성 중 발생한 엔티티·블록 효과를 조정해야 한다. 실제 생성 스케줄러,
세션 반영 및 저장에는 아직 연결되지 않았고, 시드 1의 미생성 울타리 이웃을 자동으로
완성하거나 저장할 수 있다는 뜻은 아니다.

구조물이 켜진 시드 `1`의 임시 월드를 20틱 이상 실행하고 저장된 울타리 이웃을
스트리밍한 뒤, 미생성 이웃 하나의 생성 입력을 캡처하는 검사를 추가했다. 설치된
Java 26.3으로 지형과 엔티티를 읽고 다시 쓴 뒤에도 이 검사는 실패한다. 15초 동안
틱을 계속 진행한 실행에서 하늘 조명이 안정되지 않았고 16개 청크에 미저장 변경이
있었다. 이 검사는 실시간 생성이 완성될 때까지 별도의 무시된 완료 기준으로 남긴다.

하늘 조명은 처리 범위가 떨어진 변경을 별도 그룹으로 나누어, 한 그룹에 필요한
청크가 없어도 다른 그룹을 갱신한다. 대기 중인 변경의 순서를 유지하고 누락 청크가
도착하면 나머지를 재시도한다. 분리 결과와 재시도 후 전체 조명을 Java 26.3 및
모든 입력이 있는 일괄 처리와 비교했다. 서로 연결된 조명 작업에 필요한 청크가
없으면 여전히 전체 작업을 완료할 수 없다.

화면 밖으로 나간 청크의 변경이 아직 조명 대기열에 있으면, 필요한 주변 청크를
보관하고 백그라운드 조명 스냅샷에서 읽는다. 결과는 활성 청크와 보관 청크에 각각
반영하며, 보관 청크의 일반 게임 틱은 실행하지 않는다. 대기가 끝나면 변경되지 않은
보관 청크는 다시 해제한다. 시드 `1`의 기존 진단에서는 누락된 `(12, 10)` 청크가
포함된 열과 화면 밖 다른 열을 조명 계산이 읽지 못했고, 수백 개의 변경이 대기했다.
화면 밖 보관 수정만으로 누락 청크의 생성·조명 순환 문제가 해결된 것은 아니다.

같은 조명 영역에서 일부 청크가 없어도, 직접 하늘 광원과 빛 차단 성질이 모두
바뀌지 않은 열의 변경은 대기열에서 먼저 완료할 수 있다. 같은 열에서 광원이나
차단 성질이 한 번이라도 바뀐 경우에는 그 열의 변경 순서를 전부 유지한다.
지원되지 않거나 원본을 읽을 수 없는 상태는 추측하지 않고 계속 대기한다.

조명 작업이 직접 확인한 누락 청크는 스트리밍에서 우선 읽는다. 화면 밖에서 읽은
청크는 보관 상태로 조명 계산에만 제공하고, 디스크에도 없으면 생성 후보로 넘긴다.
조명이 불완전하거나 지원되지 않는 블록이 있는 청크를 단순히 누락된 것으로
판정하지 않는다. 이 목록은 실제 실패 지점의 일부이며 모든 조명 의존성의 완전한
목록은 아니다. 생성 후보를 발견해도 실시간 생성과 저장이 완료된 것은 아니다.

이 연결을 적용한 시드 `1` 재검사에서는 15초 후에도 조명 작업이 세션에 없는
`(6, 9)`와 `(12, 10)` 청크를 기다렸다. 이 중 `(12, 10)`은 저장된 지형이 없는
생성 대상이며, 현재 생성 입력 검사는 조명이 먼저 완료되기를 요구한다. 같은 시점에
16개 청크에 미저장 변경도 있었다. 해당 변경을 보존한 생성 입력과 저장 조명 병합이
준비될 때까지 생성 결과를 세션에 반영하거나 저장하지 않는다.

바이옴과 지형을 미리 준비할 때는 별도의 중간 입력에서 미저장 블록, 바이옴과 대기
중인 조명 작업을 캡처할 수 있다. 저장 원본과 기록된 변경을 백그라운드에서 대조하고,
작업 중 입력이나 대기열이 바뀌면 바이옴·지형 작업 결과를 폐기한다. 생성 렌더
스냅샷은 `terrain`, 저장 초안은 `full` 상태일 수 있으므로 이 중간 입력은 블록과
바이옴 내용만 검증하며 청크 상태를 인증하지 않는다. 최종 반영용 검증은 그대로
유지한다. 저장 지형을 별도의 중간 지형에 조립할 때는 기록된 미저장 블록을 원본과
대조해 적용하고, 변경된 청크의 높이맵을 원본 검증 후 다시 계산할 수 있다. 원본
높이맵이 블록과 일치하지 않거나 블록의 높이 판정이 지원되지 않으면 조립을 거부한다.
이 중간 지형은 저장된 조명값을 노출하지 않으며 블록 엔티티도 확인되지 않은 상태로
표시한다. 조명·틱·엔티티·POI 병합, 틱 경계 반영과 저장은 아직 필요하다.

시드 `1`의 실제 임시 월드에서는 미저장 청크 16개가 있는 상태에서 중간 입력을
만들고, 그 안의 변경 블록과 바이옴을 실행 중 월드와 대조했다. 대기 중인 조명을
보존하고 대기열 변경 시 입력을 무효화하는 동작은 별도의 합성 테스트에서 확인했다.

같은 시드에서 누락된 `(12, 9)` 청크의 작업자를 실행해 필요한 신규 지형 18개와
저장 지형 7개를 준비했다. 대상 청크의 바이옴 1,536개는 설치된 Java 26.3의 생성
결과와 일치했다. 검사에서는 입력 캡처 중 스트리밍 결과가 도착하면 대기 위치를
구분해 틱 이후 재시도하고, 원본 관찰이 바뀌면 다시 캡처했다. 이 재시도 흐름은
실제 플레이 코디네이터에 아직 연결되지 않았다. 별도의 중간 조립에서는 저장 이웃의
미저장 블록 462개와 높이맵 2,304개 값을 실행 중인 세션과 비교했고, 대상 바이옴
1,536개를 Java와 비교했다. 최종 조립은 하늘 조명이 안정되지 않아 여전히 보류됐고,
준비한 지형이 플레이나 저장에 반영된 것은 아니다.

여러 종류의 구조물이 참조된 지형은 청크에 영향을 주는 구조물 조각과 접합점을
검사한다. 모든 가능한 순서의 부동소수점 결과가 같다고 증명되는 경우에만 순서를
자동으로 선택하고, 영향이 겹쳐 결과가 달라질 수 있으면 Java 순서를 요구한다.
누락된 구조물 원본이나 판단할 수 없는 범위는 추측하지 않는다.

실시간 연결은 다음 순서로 진행한다.

1. 미완료 조명이 필요로 하는 청크와 생성 작업의 의존성을 추적하고, 저장 조명과
   생성 조명을 같은 순서로 병합해 서로 완료를 기다리는 순환을 해소한다.
2. 미저장 지형, 높이맵, 예약 틱, 블록 엔티티, 엔티티와 POI를 같은 세션 시점에
   캡처하면서 원본 디스크 데이터와의 검증 관계를 보존한다.
3. 생성과 후처리 결과를 틱 경계에서 함께 반영하고 대기 갱신을 재실행한다.
   그 뒤 복사한 월드에서 저장·재접속 및 Java 왕복을 검증한다.
