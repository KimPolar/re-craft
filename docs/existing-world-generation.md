# 기존 월드의 미생성 청크

기존 월드에서 이동할 때 필요한 청크를 생성하려면 저장된 생성 설정과 데이터팩,
이웃 청크, 실행 중인 월드 상태를 같은 시점의 입력으로 다뤄야 한다. 현재 구현은
이 경로의 중간 단계이며 플레이 화면이나 실제 월드 쓰기에 연결되지 않았다.

`biomes` 단계의 빈 청크는 캡처된 3×3 바이옴과 구조물 시작점·참조를 이용해
지형, 표면과 동굴을 계산할 수 있다. 생성기에 연결된 데이터팩 스냅샷의 블록
레지스트리와 동굴 설정은 재사용한다. 기존 블록이나 미처리 틱이 있거나 블렌딩·
지하 재생성이 필요한 청크는 계산을 중단한다. 결과는 `terrain` 단계의 중간
데이터로, 월드 파일을 변경하지 않는다.

계산한 지형은 같은 캡처의 바이옴과 블록 레지스트리로 청크 형식으로 변환한다.
원래 청크 문서와 후처리 기록을 보존하며, 동일 캡처에서 나온 청크만 하나의
지형 작업에 모을 수 있다. 서로 다른 캡처 또는 중복 청크는 거부한다.
생성한 블록 팔레트만 원본 섹션에 결합한 부분 NBT 초안도 만들 수 있다.
원본 바이옴과 알 수 없는 태그, 구조물 정보를 보존하고 원본이 바뀌었는지
확인한다. 같은 생성 결과의 `WORLD_SURFACE_WG`, `OCEAN_FLOOR_WG`와 순서가
있는 후처리 표시를 부분 초안에 추가할 수 있다. 이미 기록된 높이맵이나
미처리 표시가 있으면 안전하게 합칠 수 있을 때까지 중단한다. 상태와 나머지
데이터는 아직 완성되지 않아 저장할 수 없다.

합성한 `biomes` 단계 입력에서 세 차원의 지형 초안을 생성한 뒤, 임시 사본의
상태만 `terrain`으로 바꾸어 설치된 Java 26.3의 청크 직렬화 코드로 읽고 다시
쓰는 테스트가 있다. 블록 상태와 바이옴, 두 월드 생성 높이맵, 후처리 표시,
구조물 정보 및 빈 틱 목록을 비교한다. 이는 실제 월드의 생성·저장이나 재접속
호환성을 검증한 것은 아니다.

이후에는 생성 결과와 원본 청크의 구조물·틱 등 나머지 데이터를 결합하고,
주변 의존 청크의 각 생성 단계를 이어서 실행해야 한다. 실제 세션에 반영하기
전에는 라이브 청크 변경, 블록 엔티티·엔티티·POI, 데이터팩과 디스크 원본을
검증해야 한다. 저장은 검증된 변경을 같은 트랜잭션에 넣고 백업과 중단 복구를
보장한 뒤에만 연결한다. 26.3 복사 월드와 Java 양쪽에서 생성 경계 및 플레이 후
재접속 결과를 비교하는 검증도 필요하다.
