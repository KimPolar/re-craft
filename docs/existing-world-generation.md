# 기존 월드의 미생성 청크

기존 월드에서 이동할 때 필요한 청크를 생성하려면 저장된 생성 설정과 데이터팩,
이웃 청크, 실행 중인 월드 상태를 같은 시점의 입력으로 다뤄야 한다. 현재 구현은
이 경로의 중간 단계이며 플레이 화면이나 실제 월드 쓰기에 연결되지 않았다.

`biomes` 단계의 빈 청크는 캡처된 3×3 바이옴과 구조물 시작점·참조를 이용해
지형, 표면과 동굴을 계산할 수 있다. 생성기에 연결된 데이터팩 스냅샷의 블록
레지스트리와 동굴 설정은 재사용한다. 기존 블록이나 미처리 틱이 있거나 블렌딩·
지하 재생성이 필요한 청크는 계산을 중단한다. 결과는 `terrain` 단계의 중간
데이터로, 월드 파일을 변경하지 않는다.

계산한 지형은 같은 캡처의 바이옴과 블록 레지스트리로 청크 형식으로 변환한다.
원래 청크 문서와 후처리 기록을 보존하며, 동일 캡처에서 나온 청크만 하나의
지형 작업에 모을 수 있다. 서로 다른 캡처 또는 중복 청크는 거부한다.
생성한 블록 팔레트만 원본 섹션에 결합한 부분 NBT 초안도 만들 수 있다.
원본 바이옴과 알 수 없는 태그, 구조물 정보를 보존하고 원본이 바뀌었는지
확인한다. 같은 생성 결과의 `WORLD_SURFACE_WG`, `OCEAN_FLOOR_WG`와 순서가
있는 후처리 표시를 부분 초안에 추가할 수 있다. 이미 기록된 높이맵이나
미처리 표시가 있으면 안전하게 합칠 수 있을 때까지 중단한다. 상태와 나머지
데이터는 아직 완성되지 않아 저장할 수 없다.

합성한 `biomes` 단계 입력에서 세 차원의 지형 초안을 생성한 뒤, 임시 사본의
상태만 `terrain`으로 바꾸어 설치된 Java 26.3의 청크 직렬화 코드로 읽고 다시
쓰는 테스트가 있다. 블록 상태와 바이옴, 두 월드 생성 높이맵, 후처리 표시,
구조물 정보 및 빈 틱 목록을 비교한다. 이는 실제 월드의 생성·저장이나 재접속
호환성을 검증한 것은 아니다.

다음 장식 단계에 필요한 기능 목록은 캡처된 3×3 저장 바이옴과 같은 데이터팩의
전역 기능 순서에서 선택할 수 있다. 전역 순서는 같은 생성기에서 재사용하며,
다른 캡처의 생성기와 계획을 혼합하거나 이웃이 빠진 경우는 거부한다. 선택된
기능과 필요한 블록·태그는 같은 데이터팩에서 배치 준비 단계까지 해석할 수 있다.
지원하지 않는 기능은 지형을 변경하기 전에 중단한다. 구조물 생성이 꺼졌거나
저장된 구조물 참조가 없는 청크는 같은 캡처에서 복원한 주변 지형과 준비된
스케줄러를 이용해 지원하는 기능을 중간 지형에 배치할 수 있다. 저장된 매장된
보물 참조는 원래의 구조물·참조 순서로 배치하며, 바뀐 경계와 원본 시작점은
같은 생성 작업에서 보존한다. 보존한 원본 청크에 변경된 보물 경계만 반영하는
부분 NBT 초안도 만들 수 있으며, 시작점·참조 수가 캡처한 데이터와 다르면
중단한다. 지원하지 않는 참조나 해석 중 버려지는 데이터가
있으면 중단한다. 별도로 출처와 시점을 확인한 초기 조명 스냅샷을 전달하면 밝기
정보가 필요한 지원 기능도 실행할 수 있다. 스냅샷은 같은 차원의 채널과 현재 중간
지형 시점에 묶이며 지형이 바뀌면 만료된다. 호출자는 조명 엔진에 청크가 등록되거나
빛이 전파되지 않았고 배치 중 표시 조명이 바뀌지 않는 상태와 스냅샷의 출처를 직접
확인해야 한다. 저장된 조명이나
실행 중인 월드의 조명을 자동으로 복원하는 기능과 다른 구조물의 배치는 아직 없다.
배치가 성공한 영역의 이전 지형 초안은 재사용하지 않는다. 이 중간 결과는
아직 플레이 세션이나 실제 월드 저장에 연결되지 않았다.

기능 배치가 닿은 청크는 현재 시점의 블록, 높이맵, 후처리 표시, 블록 엔티티,
틱, 기록된 생성 엔티티와 지원되는 보물 시작점 변경을 부분 NBT 초안으로 묶을 수 있다.
기존 프로토 청크 엔티티 뒤에 기록된 생성 엔티티를 순서대로 추가하며, 별도 엔티티
리전의 원본은 수정하지 않고 함께 보존한다. 생성 엔티티의 전체 수집 여부와 나중의
엔티티 리전 병합은 아직 검증되지 않았다.
기능 초안은 같은 데이터팩에서 분류한 배치 기능에 대해 제한된 근거를 포함한다.
주변 3×3 기능 단계가 끝나고 지금까지 실행한 모든 배치 기능이 엔티티를 생성하지
않는 것으로 확인된 경우에만 이 범위가 확인된 것으로 표시한다. 알 수 없는 기능은
확인을 무효화한다. 이 표시는 구조물, 기존 엔티티, 몹 생성이나 최종 저장의 완전성을
뜻하지 않는다.
원본 바이옴과 알 수 없는 태그를 유지하고, 기존 조명이 있는 입력은 중단한다.
이웃 청크 추가나 후속 기능 배치가 성공하면 이전 초안의 시점 검증이 실패한다.
엔티티 측면 데이터의 최종 병합과 이후 생성·조명 단계는 포함하지 않으므로 저장
가능한 청크로 취급하지 않는다.

저장된 조명이 없는 재개 지형에는 별도의 빈 조명 추적기를 만들어
`INITIALIZE_LIGHT`를 실행할 수 있다. 호출자는 주변의 기존 조명이나 라이브 엔진이
영향을 주지 않는 상황인지 확인해야 한다. 실제로 완료한 기능 단계만 등록하며,
전파 전에는 주변 3×3 청크가 같은 추적기에 등록됐는지 검사한다. 지형이 바뀌면
추적기와 전파 엔진은 만료된다. 전파 결과는 메모리상의 조명 스냅샷이며 저장된 조명
복원이나 청크 저장을 뜻하지 않는다. 전파된 청크의 부분 초안에는 해당 시점에 할당된
조명 레이어를 추가할 수 있다. 기존 섹션의 바이옴과 알 수 없는 필드는 유지하고,
원본 조명이 있거나 조명 컬럼이 없거나 범위 밖 레이어가 있으면 중단한다. 후속 전파나 지형 변경은
초안의 시점 검증을 무효화한다. 청크 상태와 엔티티·저장 의존성은 확정하지 않는다.

생성기에서 몹 생성을 끄거나 현재 `spawn_mobs` 규칙이 꺼진 경우에는 조명이 끝난
청크의 `SPAWN` 단계를 진행할 수 있다. 호출자는 규칙을 같은 월드 세션에서 읽고
라이브 변경과 저장 전 원본을 별도로 확인해야 한다. 이 단계는 기존 프로토 엔티티와
기록된 기능 엔티티를 그대로 유지한다. 일반적인 몹 생성 경로와 전체 엔티티 수집,
`FULL` 전환 및 저장은 아직 연결되지 않았다.

몹 생성이 켜진 경우에는 캡처된 바이옴, 차원·데이터팩 속성, 호출자가 제공한 시계와
월드 시드를 이용해 Java의 생성 후보를 순서대로 계산할 수 있다. 후보가 전혀 없을 때만
엔티티를 추가하지 않고 `SPAWN`을 완료한다. 후보가 생기면 같은 후보를 유지하며,
충돌 검사와 엔티티 생성이 연결될 때까지 완료하지 않는다. 시계·규칙·라이브 월드가
바뀌었는지는 호출자가 별도로 확인해야 한다.

이후에는 생성 결과와 원본 청크의 구조물·틱 등 나머지 데이터를 결합하고,
주변 의존 청크의 각 생성 단계를 이어서 실행해야 한다. 실제 세션에 반영하기
전에는 라이브 청크 변경, 블록 엔티티·엔티티·POI, 데이터팩과 디스크 원본을
검증해야 한다. 저장은 검증된 변경을 같은 트랜잭션에 넣고 백업과 중단 복구를
보장한 뒤에만 연결한다. 26.3 복사 월드와 Java 양쪽에서 생성 경계 및 플레이 후
재접속 결과를 비교하는 검증도 필요하다.
