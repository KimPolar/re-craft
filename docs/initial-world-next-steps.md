# 초기 월드 생성: 현재 검증과 다음 단계

2026-11-14 Windows 디버그 빌드에서 구조물이 켜진 시드 `1`과 `-1`의
초기 생성·플레이어 스폰·임시 저장 파이프라인을 각각 실행했다. 저장된
지형의 섹션, 높이맵, 블록 엔티티, 예약 틱과 후처리 표시를 생성 초안과
비교했다. 이 파이프라인은 실제 저장 폴더에 월드를 게시하거나 게임을
시작하지 않는다.

같은 날 시드 `-1` 임시 월드의 지형 청크 11개와 엔티티 청크 1개를 Java
26.3 직렬화기로 읽고 다시 썼으며 엔티티 헤더 2개를 확인했다. POI 청크는
없었다. 이 검사는 Java 게임에서 월드를 열거나 Java가 같은 시드로 생성한
지형과 블록별로 비교하지 않는다. 검사한 등록 청크에서는 준비된 폐허 포털
시작점이 없어 폐허 포털 저장·배치를 확인하지 못했다.

이전 기록의 시드 `-1` 초기 생성 실패는 현재 확인한 설정에서는
재현되지 않았다. 이는 해당 시드의 모든 구조물이나 월드 생성이 바닐라와
같다는 뜻은 아니다.

구조물 생성이 켜진 기존 월드에서도 혼합 캡처 지형의 장식 단계에 빈 구조물
참조와 저장된 묻힌 보물 참조를 사용할 수 있다. 보물의 변경된 시작점은 원본에
연결된 별도 초안으로 보존한다. 원본 청크가 후처리 대상 밖이면 그 원본을
별도 초안으로 반환하며, 향후 저장은 생성 청크와 원본 변경을 함께 처리해야
한다. 합성 저장 청크에서 기존 저장 청크 장식 경로와
블록 및 구조물 NBT를 비교하고, 미지원 참조와 실패 시 상태 보존을 검사했다.
다른 구조물, 새 구조물 시작점, 플레이 중 생성과 월드 저장은 아직 이 경로에
연결되지 않았다.

저장 계획은 완성된 새 청크 리전과 저장된 보물 시작점의 높이 변경을 한 번에
추가하고 같은 트랜잭션으로 기록할 수 있다. 원본의 다른 NBT는 보존하며,
데이터팩·설정·원본과 새 청크 및 엔티티·POI 부재를 캡처하고 재확인해야 한다.
임시 월드에서 프로토청크 보존, 원본 변경 시 중단과 서로 다른 리전의 원자적
저장을 검사했다.
캡처된 후처리 결과는 기존 POI 저장 데이터가 없는 청크에 대해 블록 상태로
POI 초안을 구성한다. 기존 POI가 있는 청크는 미확인 상태로 남기며, 저장
전에 디스크와 라이브 티켓 상태를 다시 확인해야 한다. 엔티티 및 나머지 저장
완전성도 아직 확인되지 않아 이 결과로 실제 월드 저장을 승인하지 않는다.
후처리는 각 블록의 변경 전후 상태를 순서대로 기록한다. 같은 위치가 다시
바뀌어 최종 블록이 원상태가 된 경우에도 POI 변경을 놓치지 않는다. POI가
실제로 바뀐 후처리 결과는 Java의 갱신 순서와 기존 티켓을 반영하는 경로가
검증될 때까지 블록만으로 POI 초안을 만들지 않는다.
Java 26.3의 `WorldGenRegion.setBlock`도 POI 변경을 서버에 예약한다. 따라서
장식 단계에서 해당 쓰기의 POI 변경을 청크별로 기록하며, 광맥의 직접 섹션
쓰기는 이 기록에 포함하지 않는다. 서버 큐의 실행 순서와 기존 POI를 아직
재현하지 않았으므로 생성 중 POI 변경이 있는 청크의 스냅샷 구성도 중단한다.
실행 순서가 별도로 확인된 POI 알림은 기존 저장 기록에 순서대로 적용할 수
있다. 같은 종류의 기존 POI와 티켓을 유지하고, 다른 종류로 덮어쓸 때 Java의
해시 슬롯 순서를 보존한다. 이 초안은 서버 큐의 순서, 라이브 POI 인덱스나
티켓 변경을 증명하지 않으며 실제 월드 저장을 승인하지 않는다.

다음 순서로 진행한다.

1. 폐허 포털 시작점과 참조가 실제로 포함되는 시드·청크를 고정하고,
   배치 결과와 저장된 시작점·참조를 Java 26.3과 비교한다. 그 밖의 미지원
   구조물과 엔티티도 생성 중 명시적으로 실패하는 사례부터 처리한다.
2. 여러 시드·설정·데이터팩에 대해 생성 결과와 Java의 지형·구조물·엔티티를
   비교하고, 임시 저장본을 양쪽 구현에서 열고 저장하는 왕복을 검증한다.
3. 검증한 생성과 저장을 생성 화면의 진행 상태·취소·오류 처리에 연결한다.
   완전성과 안전성이 확인된 결과만 실제 저장 폴더에 게시하고 세션을 연다.
4. 플레이 중 빠진 청크 생성·저장과 재접속 복원을 연결하고, 경계 이동과
   취소·실패 시 기존 데이터 보존을 검사한다. 이후 세 차원과 사용자
   데이터팩으로 범위를 확장한다.
5. 릴리스 빌드에서 각 생성 단계의 시간과 메모리를 측정하고, 결과 및 틱·난수
   순서를 유지하는 최적화만 적용한다. 화면 성능은 별도 조건에서 측정한다.
