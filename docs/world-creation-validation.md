# 새 월드 생성과 플레이 연결 검증 계획

## 현재 확인한 범위

Java 왕복 검사는 구조물이 켜진 시드 `-1`과 `42` 오버월드를 각각 임시로
생성한다. 생성한 플레이어의
저장된 지형 청크를 리전 파일에서 열거하고 Java 26.3의
`SerializableChunkData`로 읽고 다시 쓴 뒤 블록, 바이옴, 조명과 일부 청크
데이터를 비교한다. 저장된 엔티티 청크의 좌표, 엔티티 식별자와 위치를 Java에서
읽고 NBT를 다시 쓴 뒤 필드 값을 비교한다. `level.dat`, 월드 생성 설정과
플레이어의 위치·차원·UUID도 검사한다.

2026-11-08 Windows 디버그 빌드에서 지형 청크 11개와 엔티티 청크 1개
(엔티티 헤더 2개)의 검사가 통과했으며 실행 시간은 약 363초였다. 이 월드에는
저장된 POI 청크가 없어 실제 POI 검사는 실행되지 않았다. 이 결과는 한 월드의
검사한 필드에 한정된다. 엔티티 전체를 Java 객체로 읽은 것이 아니고 Java 게임
자체에서 월드를 열거나 플레이한 결과도 아니다. POI, 사용자 데이터팩 및 나머지
차원의 보존을 증명하지 않는다.

2026-11-10 같은 Windows 환경에서 현재 작업 트리로 다시 실행한 결과도
지형 청크 11개와 엔티티 청크 1개(엔티티 헤더 2개)를 통과했다. POI 청크는
없었으며, 초기 플레이 세션의 대상 청크에는 비어 있지 않은 엔티티 청크가
없었다. 검사는 약 145초가 걸렸다. 시간은 단일 디버그 실행으로, 릴리스
성능이나 이전 실행과의 성능 차이를 판단하는 기준이 아니다. 이번 검사도 Java
게임 실행 및 전체 엔티티 동작의 왕복을 포함하지 않는다.

2026-11-10에는 같은 작업 트리의 검사를 시드별로 실행할 수 있게 확장하고,
구조물이 켜진 시드 `42`도 검사했다. 임시 저장된 지형 청크 11개와 엔티티
청크 1개를 Java 26.3으로 읽고 다시 썼으며 엔티티 헤더 4개를 확인했다.
POI 청크는 없었고 초기 세션의 대상 청크에 비어 있지 않은 엔티티 청크는
없었다. 약 124초가 걸린 단일 디버그 실행이며, 실제 게임에서 월드를 열거나
Java가 생성한 같은 시드의 지형과 블록 단위로 비교한 검사는 아니다.

두 시드를 다시 검사하면서 임시 저장본과 Java가 트랜잭션 저장본을 다시 쓴
결과 사이의 청크 좌표·데이터 버전·구조물·블록 엔티티·예약 틱·높이맵·
후처리 표시도 비교했다. 두 시드 모두 지형 청크 11개와 엔티티 청크 1개가
통과했고 POI 청크는 없었다. 엔티티 헤더는 각각 2개와 4개였다.

같은 시드의 생성 리전 초안을 신규 청크 저장 트랜잭션으로 빈 임시 월드에
기록한 뒤 동일한 Java 검사를 다시 수행했다. 2026-11-08 Windows 디버그
빌드에서 지형 청크 11개, 엔티티 청크 1개(엔티티 헤더 2개)가 통과했고
POI 청크는 없었다. 저장된 청크 좌표 집합이 기존 스테이징 결과와 같은지도
확인했다. 이 검사는 약 530초였다. 한 시드와 검사한 필드에 한정되고,
실제 Java 게임에서 월드를
열거나 기존 월드의 주변 청크와 함께 생성한 검사는 아니다.

별도의 합성 검사에서는 Java 26.3이 기존 리전과 새 리전에 추가한 지형 두
청크 및 엔티티·POI 항목을 읽고 기존 청크가 유지되는 것을 확인했다. 이 검사는
저장 형식의 일부를 확인하며 실제 월드 생성 결과의 바닐라 일치를 뜻하지 않는다.

수중 마그마가 나무 판자나 원목 계열을 이웃으로 만날 때의 면 판정을
Java 26.3과 비교했다. 바닐라 나무 상태와 여섯 방향의 978개 조합이
일치하며, 미지원 이웃을 만났을 때는 생성 중인 변경을 되돌린다. 이 검사는
마그마 인접 블록의 면 판정에 한정되고 전체 구조물·월드 생성을 보증하지 않는다.
반 블록과 계단도 방향별 면을 판정한다. 설치된 26.3의 8,366개 상태와
50,196개 면을 Java와 비교했으며, 아래·위·이중 반 블록에 따른 실제 마그마
배치 여부를 별도로 검사한다.

초기 월드의 후처리에서 아직 변환되지 않은 이웃 청크가 필요하면 해당 청크를
준비하고 미완료 시도를 버린 뒤 재시도한다. 기존에 완료된 청크의 틱은 재실행하지
않는다. 이전에는 시드 `0`과 `42`가 이웃 청크 `(-3, 0)`에서 중단됐지만,
변경을 분리한 소스에서 시드 `0`의 생성·임시 저장과 시드 `42`의 생성 후
임시 저장 취소·재시도가 통과했다. 이는 Java와 전체 지형을 비교하거나 월드를
실제로 게시한 검사는 아니다.

직소 템플릿의 엔티티는 Java처럼 `blockPos`를 회전한 뒤 현재 청크 배치 범위와
비교한다. 범위 밖 엔티티 때문에 해당 청크의 블록 배치가 중단되지 않으며,
범위 안의 바닐라 쿠션은 위치·방향과 새 UUID를 적용해 생성 엔티티로 기록한다.
쿠션의 저장 NBT는 설치본 템플릿의 쿠션 224개와 네 회전, 색상·방향 조합
320건을 Java 26.3과 비교했다. 실제 청크 생성 스케줄의 기록과 미지원 엔티티가
섞였을 때 롤백도 검사했다. 좌표 변환은 별도로 1,536건을 Java와 비교했다.
현재는 확인된 바닐라 쿠션, 타이가 마을 갑옷 거치대와 마을 주민 NBT를 처리하며
다른 엔티티나 알 수 없는 데이터는 거부한다. 갑옷 거치대 두 개의 장비와 포즈를 포함한
저장 NBT는 네 방향과 두 회전 중심의 16조건에서 Java 26.3과 비교했다. 바닐라
쿠션을 넣은 합성 직소 한 건은 생성·조명·스폰·후처리 후
엔티티 리전에 저장하고, Java 26.3에서 쿠션 객체로 읽어 다시 쓴 NBT를 비교했다.
쿠션의 렌더링·게임 동작과 전체 생성 월드의 왕복은 아직 검증되지 않았다.

사용자 템플릿으로 교체한 난파선에서도 확인된 바닐라 쿠션을 기록한다. 난파선의
회전 중심을 적용한 쿠션 224개 × 네 회전의 NBT를 Java 26.3과 비교했다. 실제
청크 생성 스케줄의 기록, 배치 범위 안의 미지원 엔티티로 실패할 때 롤백과 범위 밖
엔티티의 무시를 검사했다. 이는 쿠션 외의 난파선 엔티티나 사용자 데이터팩 전체에
대한 지원을 뜻하지 않는다.

주민 유형 선택은 바이옴 태그가 아닌 바이옴 ID를 사용하며, 유효한 기존 주민
정보가 있으면 해당 유형을 유지한다. 바닐라 바이옴 67개와 사용자·비등록 바이옴,
마을 주민 템플릿 15개를 Java 26.3의 유형 확정 동작과 비교했다. 확인된 주민
템플릿은 직소 청크 생성에 연결했으며 지역 난수를 해저 유적·오두막과 공유한다.
15개 템플릿의 네 방향, 두 난수 방식과 네 시드에서 저장 NBT 및 후속 난수를
Java와 비교하고, 여러 주민 배치의 난수 순서와 실패 시 롤백을 검사했다. Java
비교는 주민의 경로 탐색과 두뇌 갱신을 대체한 객체에 한정된다. 어린 주민과 성인
주민을 각각 넣은 합성 직소 두 건은 청크 생성·조명·스폰·후처리 후 엔티티 리전
초안을 파일로 쓰고, Java 26.3 주민 객체로 읽어 다시 쓴 NBT를 비교했다. 전체
월드 왕복과 플레이 중 AI, 확인되지 않은 주민 데이터는 아직 지원하지 않는다.

## 게시 전 검증 순서

1. 임시 월드에 저장된 모든 지형·엔티티·POI 청크와 해당 좌표를 열거한다.
   Java가 각 청크를 읽고 다시 쓴 뒤 블록, 바이옴, 조명, 높이맵, 구조물,
   블록 엔티티, 예약 틱, 후처리 표시와 엔티티·POI 데이터를 비교한다.
   누락된 청크와 빈 청크의 의미도 각각 확인한다.
2. 여러 시드와 구조물 설정, 보너스 상자, 게임 모드와 데이터팩을 검사한다.
   네더·엔드와 사용자 차원도 생성 및 저장 경로가 준비되는 대로 같은
   검증에 포함한다. 설치된 Java의 원본 월드와 비교할 때는 복사본만 쓴다.
3. Java에서 임시 월드를 열어 저장한 뒤 다시 읽고, 구현체에서도 열고
   저장한 다음 Java로 재확인한다. 플레이어·게임 규칙·시간·날씨·데이터팩과
   미지원 데이터가 유지되는지 검사한다.
4. 위 검증과 생성 데이터 완전성 검사를 통과한 경로만 실제 저장 폴더에
   게시한다. 오류 또는 취소 시 기존 월드를 변경하지 않고 재시도할 수
   있어야 한다. 생성 화면의 진행 상태와 취소를 작업자에 연결하고, 생성
   직후 세션을 시작한다.
5. 플레이 중 미생성 청크의 생성과 저장, 재접속 후 플레이어 복원을 연결하고
   각 단계의 실패·취소·경계 이동을 검사한다. 검증하지 않은 기능은 완성이나
   바닐라 호환으로 표시하지 않는다.

임시 월드 저장은 메타데이터·청크 기록·외부 청크 기록·재검증·파일 목록 생성의
진행 상황을 보고하고 각 확인 지점에서 취소할 수 있다. 취소하면 임시 트리를
삭제하며 기존 파일은 변경하지 않는다. 단일 압축·파일 시스템 호출 도중에는
중단하지 않고 다음 확인 지점에서 취소한다. 생성 결과를 백그라운드 저장 작업자에
넘기면 진행 상황과 취소 요청을 연결하며, 취소하거나 오류가 반환되면 임시 트리를 정리하고
생성 결과를 반환해 재시도할 수 있다. 데이터팩 복사와 검증, 임시 월드 파일의
해시 계산 중에는 64 KiB 단위와 파일 경계에서 취소를 확인한다. 단일 파일 시스템
호출은 완료될 때까지 기다린다. 실제 월드 게시와 생성 화면은 아직 이 작업자에
연결되지 않았다.

생성 파이프라인에서 저장 취소 또는 실패 후 같은 생성 결과를 다시 저장할 수
있다. 저장 경로를 바꿔 재시도할 수 있으며 기존 구조물 설정과 시각은 유지한다.
작업 스레드를 시작하지 못하거나 생성 결과를 넘기기 전에 연결이 끊긴 경우에도
생성 결과를 돌려준다. 이 재시도 경로는 아직 생성 화면에 연결되지 않았다.

플레이 중 생성한 청크를 저장하기 위한 기반으로, 새 지형과 엔티티·POI의
저장 여부를 하나의 저장 계획에 추가할 수 있다. 세 항목 중 기존 데이터가
하나라도 있으면 전체 트랜잭션을 중단하며, 새 지형 리전의 생성도 중단 후
복구할 수 있다. 생성기의 완성된 리전 초안도 지형과 부속 데이터의 대응을
확인해 저장 계획으로 옮길 수 있다. 이 경로는 생성 결과의 완전성을 증명하지
않으며, 아직 게임 세션이나 이동 중 청크 생성에 연결되지 않았다.

생성이 참고한 기존 지형·엔티티·POI 청크와 비어 있던 청크는 저장 계획의
읽기 의존성으로 지정할 수 있다. 저장 전 원본이 바뀌었거나 비어 있던 리전이
생겼으면 트랜잭션을 중단하고, 읽기만 한 리전은 다시 쓰지 않는다. 호출자가
관찰한 모든 입력을 빠짐없이 지정해야 하며, 메모리의 미저장 변경과 생성 설정의
동시 변경은 별도로 보호해야 한다. 생성 작업자 연결은 아직 남아 있다.

잠긴 월드 리더에서 선택한 청크의 지형·엔티티·POI 원본을 함께 수집하고,
같은 월드 세션의 저장 계획에 의존성을 일괄 추가할 수 있다. 저장 전 리더가
보유한 리전 핸들을 닫으며 저장 중 새 리전 읽기는 오류를 반환하므로 호출자가
재시도해야 한다. 청크 스트리머는 지형과 부속 파일을 한 보호 구간에서 읽지만,
읽은 결과를 세션에 반영하는 시점과 저장은 여전히 별도로 조정해야 한다.
이 캡처에는 세션에서 아직 저장하지 않은 변경, 데이터팩 및 생성 설정이 포함되지
않으므로 실시간 청크 생성에 연결하기 전 별도 검증이 필요하다.

생성 설정 파일은 같은 월드 세션에서 별도로 캡처해 생성에 사용하고 저장 계획의
읽기 의존성으로 지정할 수 있다. 저장 전 원본 바이트가 바뀌면 중단하며,
저장 트랜잭션의 반영 전후에도 파일을 다시 확인한다. 다른 월드 세션의 캡처를
섞을 수 없다. 이 보호는 호출자가 설정 스냅샷을 실제 생성에 사용하고 저장 계획에
지정해야 적용된다. 데이터팩, 메모리의 미저장 변경과 생성 작업자 연결은 여전히
별도로 처리해야 한다.

생성 설정과 선택한 지형·엔티티·POI 원본은 하나의 쓰기 배제 구간에서 함께
캡처할 수 있다. 묶음을 저장 계획에 추가할 때 중복이나 다른 세션이 발견되면
계획에 일부만 추가하지 않는다. 캡처 뒤 설정 또는 이웃 청크가 바뀐 경우 저장이
중단되고, 다시 캡처한 입력으로 재시도하는 합성 검사를 추가했다. 캡처 도중
다른 스레드의 저장이 거부되는지도 확인했다. 이 캡처도
호출자가 필요한 모든 입력을 지정해야 하며 데이터팩과 미저장 게임 상태는 포함하지
않는다.

기존 월드의 캡처된 생성 설정으로 노이즈 생성기를 준비하는 경로를 추가했다.
활성 데이터팩이 같은 차원을 정의하면 저장된 차원보다 우선하며, 선택한 팩은
월드의 현재 `level.dat` 선택 목록과 같은 월드의 파일에서 캡처해 준비 과정에서
스냅샷으로 유지한다. 캡처 마지막 검사에서 선택 목록이나 팩 파일이 달라져
있으면 중단한다. 외부 프로그램의 쓰기를 잠그는 것은 아니다.
설치된 26.3의 세 차원에서 시드 -42의
원점 바이옴을 기존 프리셋 준비 경로와 비교했고, 합성 데이터팩의 차원 재정의와
구조물 비활성 설정을 검사했다. 생성 컨텍스트를 저장 계획에 연결하면 캡처한
데이터팩 트리와 선택 목록을 저장 전 및 트랜잭션 반영 전후에 확인한다. 반영
도중 팩이나 읽기 전용 선택 파일이 바뀐 경우에는 해당 파일을 덮어쓰지 않고
리전 변경을 복구할 수 있다. 외부 프로그램의 쓰기를 잠그지는 않으며, 이 보호는
호출자가 컨텍스트를 계획에 연결할 때 적용된다. 이 경로는 아직 실행 중 청크
생성에 연결되지 않았고, 미저장 게임 상태와 전체 지형의 Java 차등 검증은
별도로 필요하다.

기존 월드 생성기 준비 시 스케줄러가 계산한 현재 요청과 주변 단계 의존성의
청크를 함께 캡처하는 경로를 추가했다. 겹치는 요청은 중복 없이 합쳐지며, 빈
요청이나 좌표 범위 초과는 중단한다. 합성 월드에서 이웃 범위와 추가 요청 뒤의
재캡처를 확인했고, 설치된 26.3의 세 차원 생성기 준비에도 적용해 검사했다.
스케줄 확장 후에는 다시 캡처해야 한다. 스케줄 밖에서 동적으로 읽는 데이터와
세션의 미저장 변경은 이 경로가 추적하지 않으며, 기존 청크를 생성 작업에
공급하거나 결과를 플레이에 반영하는 기능은 아직 연결되지 않았다.

기존 월드에서 중간 생성 단계로 저장된 청크도 읽기 의존성으로 캡처하고,
주변에 새 청크를 저장할 때 원본 변경 여부를 확인해 보존한다. 알 수 없는
상태는 거부하며 중간 단계 청크의 덮어쓰기는 허용하지 않는다. 생성 스케줄은
복원된 청크의 단계를 일괄 반영할 수 있지만, 먼저 각 단계의 지형과 부속
데이터를 실제로 복원해야 한다. 이 연결과 플레이 중 생성은 아직 미구현이다.

캡처한 기존 청크에서 각 차원의 저장 바이옴 팔레트를 복원해 생성기의 바이옴
이웃 데이터로 사용할 수 있다. 선택된 데이터팩의 바이옴 레지스트리를 확인하며,
누락된 섹션과 미지원 ID는 거부한다. 세 바닐라 차원의 합성 저장 청크와
Java 26.3 팔레트의 좌표별 해석을 검사했다. 지형·구조물·조명 복원이나
실행 중 청크 생성의 완성을 뜻하지 않는다.

캡처된 청크의 블록 팔레트, 저장된 여섯 종류의 높이맵과 순서가 있는 후처리
표시를 읽기 전용 생성 입력으로 복원할 수 있다. 블록 상태는 확인된 레지스트리와
대조하고 알 수 없는 상태는 거부한다. 높이맵은 블록에서 다시 계산하지 않으며,
저장값이 없거나 길이가 다르면 미준비 상태로 둔다. 합성 청크에서 세 차원의
복원을 검사하고 저장 높이맵의 좌표별 값을 Java 26.3과 비교했다. 미저장 세션
변경, 구조물·엔티티 데이터와 실제 생성 스케줄 연결은 여전히 별도로 필요하다.

복원한 지형을 현재 세션의 같은 청크와 비교하고, 생성 작업 중 관련 청크가
바뀌거나 스트리밍·조명 반영이 대기하면 결과 적용 전 검증이 실패한다. 청크
참조를 공유하므로 관련 없는 청크의 변경으로 전체 지형을 복사하지 않는다.
이 검사는 지형에 한정된다. 블록 엔티티의 실시간 내부 상태, 엔티티·POI,
높이맵·후처리 변화, 시간, 데이터팩과 디스크 의존성은 각각 따로 보호해야 한다.

기존 청크의 구조물 참조는 활성 구조물 레지스트리를 사용해 복원하며, 각 구조물의
좌표 집합을 Java 26.3의 해시 순서로 다시 구성한다. Java가 범위 밖 좌표나 미등록
구조물을 버리는 경우는 별도로 보고해 원본 데이터를 보존할 수 있게 한다. 여러
구조물 키 사이의 Java 순서는 아직 확립되지 않았다.

캡처한 구조물 시작점은 활성 데이터팩의 정의를 사용해 보물, 오두막, 폐광과
직소 조각을 복원하고 원본 NBT와 참조 범위를 보존한다. 지원하지 않는 구조물이나
조각 데이터는 중단한다. 보물·오두막·폐광은 Java 직렬화 데이터로 확인했고,
직소 조각 32개도 Java 26.3이 저장한 데이터와 비교했다. 나머지 구조물과 실제
기존 월드 경계에서의 지형 생성은 아직 검증되지 않았다.

캡처된 구조물 참조와 시작점에서 지형 보정 입력을 만들 수 있다. 같은 구조물의
참조 순서와 조각·직소 접합점의 순서를 유지하며, 누락되거나 버려진 참조는
중단한다. 구조물 종류 사이의 Java 순서는 호출자가 제공해야 한다. Java가 저장한
직소 조각 32개와 세 차원의 합성 저장 청크로 검사했으며, 실제 월드의 지형 생성과
플레이 중 청크 생성에는 아직 연결되지 않았다.

저장된 바이옴 단계 청크의 구조물 참조를 복원해 노이즈 생성에 적용하는 경로를
추가했다. 합성 데이터에서 구조물 보정이 블록 생성에 영향을 주고 계산 문맥이
복원되는지 확인했으며, 세 바닐라 차원의 합성 캡처 청크에서도 중간 노이즈 결과를
검사했다. 이 결과는 완성 청크가 아니다. 기존 청크와의 블렌딩, 이웃 단계 의존성,
실시간 변경, 후속 생성 및 저장은 아직 연결·검증되지 않았다.

## 성능 측정

디버그 실행 시간은 릴리스 성능의 기준으로 쓰지 않는다. 동일한 시드와
설정으로 릴리스 빌드의 준비·지형·구조물·장식·조명·저장 시간을 나누어
측정하고 CPU와 메모리 사용량을 함께 기록한다. 병목을 측정한 다음 결과와
틱·난수 순서를 보존하는 최적화를 적용하고, 변경 전후의 생성 결과를 다시
비교한다. 최종 화면 성능은 동일한 월드와 카메라의 1080p·12청크 조건에서
별도로 측정한다.
