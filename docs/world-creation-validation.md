# 새 월드 생성과 플레이 연결 검증 계획

## 현재 확인한 범위

작업 트리의 `generated_world_spawn_chunk_round_trips_through_java` 검사는
구조물이 켜진 시드 `-1` 오버월드를 임시로 생성한다. 생성한 플레이어의
스폰 청크를 Java 26.3의 `SerializableChunkData`로 읽고 다시 쓴 뒤 블록,
바이옴, 조명과 일부 청크 데이터를 비교한다. `level.dat`, 월드 생성 설정과
플레이어의 위치·차원·UUID도 검사한다.

2026-11-08 Windows 디버그 빌드에서 이 검사는 통과했으며 실행 시간은 약
356초였다. 이 결과는 스폰 청크 한 개와 검사한 필드에 한정된다. Java 게임
자체에서 월드를 열거나 플레이한 결과가 아니며, 다른 청크와 엔티티·POI,
사용자 데이터팩 및 나머지 차원의 보존을 증명하지 않는다. 이 검사의
작업자 변경과 Java 검사 코드는 현재 별도 미커밋 작업에 포함되어 있다.

## 게시 전 검증 순서

1. 임시 월드에 저장된 모든 지형·엔티티·POI 청크와 해당 좌표를 열거한다.
   Java가 각 청크를 읽고 다시 쓴 뒤 블록, 바이옴, 조명, 높이맵, 구조물,
   블록 엔티티, 예약 틱, 후처리 표시와 엔티티·POI 데이터를 비교한다.
   누락된 청크와 빈 청크의 의미도 각각 확인한다.
2. 여러 시드와 구조물 설정, 보너스 상자, 게임 모드와 데이터팩을 검사한다.
   네더·엔드와 사용자 차원도 생성 및 저장 경로가 준비되는 대로 같은
   검증에 포함한다. 설치된 Java의 원본 월드와 비교할 때는 복사본만 쓴다.
3. Java에서 임시 월드를 열어 저장한 뒤 다시 읽고, 구현체에서도 열고
   저장한 다음 Java로 재확인한다. 플레이어·게임 규칙·시간·날씨·데이터팩과
   미지원 데이터가 유지되는지 검사한다.
4. 위 검증과 생성 데이터 완전성 검사를 통과한 경로만 실제 저장 폴더에
   게시한다. 오류 또는 취소 시 기존 월드를 변경하지 않고 재시도할 수
   있어야 한다. 생성 화면의 진행 상태와 취소를 작업자에 연결하고, 생성
   직후 세션을 시작한다.
5. 플레이 중 미생성 청크의 생성과 저장, 재접속 후 플레이어 복원을 연결하고
   각 단계의 실패·취소·경계 이동을 검사한다. 검증하지 않은 기능은 완성이나
   바닐라 호환으로 표시하지 않는다.

## 성능 측정

디버그 실행 시간은 릴리스 성능의 기준으로 쓰지 않는다. 동일한 시드와
설정으로 릴리스 빌드의 준비·지형·구조물·장식·조명·저장 시간을 나누어
측정하고 CPU와 메모리 사용량을 함께 기록한다. 병목을 측정한 다음 결과와
틱·난수 순서를 보존하는 최적화를 적용하고, 변경 전후의 생성 결과를 다시
비교한다. 최종 화면 성능은 동일한 월드와 카메라의 1080p·12청크 조건에서
별도로 측정한다.
