# 새 월드의 플레이 및 저장 연결

## 확인한 범위

시드 `-1`의 구조물 생성에서 폐허 포털이 포함된 청크를 조명 단계까지
완료했다. 같은 시드의 초기 월드에 포털 주변 청크를 추가해 임시 저장한 뒤,
저장된 21개 청크와 포털 구조물 시작점·참조를 검사하고 플레이 세션으로
다시 열었다. 포털 주변 두 청크의 바이옴 표본과 구조물 시작점·참조는 설치된
Java 26.3과 비교했다. 이 검사는 전체 블록 배치나 월드 전체의 바닐라 일치를
증명하지 않는다.

플레이어 입력과 한 틱을 실행한 뒤 같은 경로로 저장하는 검사는 아직 실패한다.
처리되지 않은 `PostProcessing`이 남은 청크가 세션에 들어오면 저장 계획은
쓰기 전에 중단한다. 보존된 테스트 월드의 복사본에서 재현한 결과, 이러한
청크에는 물·울타리 등을 포함한 후처리 표시가 있고, 일부 청크는 틱 준비에
필요한 3×3 `FULL` 이웃도 갖추지 못했다. 표시를 삭제하거나 확인을 건너뛰면
실행되지 않은 블록·유체 갱신과 틱을 잃을 수 있다.

초기 생성이 끝난 직후 추가 청크 작업이 시작되기 전에 취소되면 완료된 생성
결과와 남은 작업을 보존한다. 다시 시도할 때는 추가 청크를 먼저 처리한 뒤
임시 저장한다. 작업자 시작이나 시작 전 입력 검증이 실패해도 생성 결과를
돌려준다. 실제 26.3 생성에서 취소·입력 오류·재시도 및 임시 저장을 확인했다.
이미 실행 중인 생성 작업의 취소·실패 후 부분 결과를 재사용하는 기능과 실제
생성 화면 연결은 아직 지원하지 않는다.

저장 청크의 격리된 틱 준비 결과에서 블록 변경과 예약 틱을 함께 세션에 반영할
수 있다. 원본과 현재 청크, 높이맵, 블록 엔티티 및 틱 큐를 확인한다. 호출자는
실제 홀더 콜백의 실행 순서를 지켜 결과를 적용해야 한다. 이웃 청크로 물이 흐른 뒤 이어서
다음 청크를 처리하는 두 콜백의 블록 상태와 유체 틱은 Java 26.3과 비교했다.
블록 엔티티나 POI 자체의 변경, 아이템 생성과 용암 반응 이벤트 등은 아직 이 경로에서
처리하지 않으며, 필요한 효과가 있으면 반영을 중단한다.

실제 시드 `-1` 생성 월드의 복사본에서는 `(20, 20)` 청크의 후처리가 예약한
틱 12개를 작업자로 처리하고, 백업을 포함한 부분 저장 뒤 다시 읽어 확인했다.
이 청크에서는 블록과 조명 변경이 발생하지 않았으므로, 이 검사는 실제 생성
월드에서 블록 변경이나 조명의 저장까지 검증하지 않는다.

저장된 3×3 청크 읽기와 재구성도 작업자에서 수행한다. 작업 시작 시 세션의
상태와 월드 잠금의 세대를 고정하고, 청크를 읽는 사이 취소와 월드 변경을
확인한다. 누락되었거나 `FULL`이 아닌 청크는 처리하지 않으며, 실제 홀더의
준비 상태와 콜백 실행 순서는 별도로 제공받아야 한다. 이 작업자는 아직 실제
게임 루프에 연결되지 않았다.

청크 홀더의 `FULL` 생성 미래는 로딩 수준이 내려갈 때 대기 중인 요청만
취소하고, 이미 완료된 결과는 보존한다. 취소 뒤 같은 홀더의 작업이 늦게
완료되면 현재 요청에 결과를 전달하며, 다른 홀더의 결과는 거부한다. 이
생명주기는 Java 26.3과 비교했고, 취소된 이웃 때문에 이전 틱 요청이 준비된
것으로 바뀌지 않는지도 검사했다. 실제 홀더 맵과 스트리밍 결과의 연결은
아직 남아 있다.

로딩 티켓의 거리 갱신을 홀더 관리 경계에 연결해 블록 틱에는 3×3,
엔티티 틱에는 5×5 `FULL` 결과를 요청한다. 생성 요청은 완료 전에는 대기
상태이며, 플레이어 로딩의 작업 슬롯도 엔티티 미래가 끝나기 전에는 해제하지
않는다. 홀더가 빠진 뒤 새로 만들어지면 이전 작업의 결과를 거부하고,
후속 콜백이 남아 있는 홀더는 즉시 제거하지 않는다. 이 연결은 합성 생성
완료 이벤트로 검사했으며, 실제 청크 읽기·생성과 게임 루프에는 아직 연결되지
않았다.

완료된 후처리는 원본 청크 지문과 함께 세션에 보관해, 저장 전 다음 콜백이 같은
원본을 읽더라도 이미 처리한 표시를 다시 실행하지 않는다. 작업 도중 지형이나
높이맵, 블록 엔티티가 바뀌면 결과를 거부한다. 조명 검사는 보류된 작업으로
전달하며, 실제 플레이 중 홀더와 실행기 연결 및 조명 결과의 전체 Java 비교는
아직 남아 있다. 이 검사는 플레이 가능한 새 월드의 저장 완료를 뜻하지 않는다.

## 연결 순서

1. 로딩 티켓과 실제 청크 홀더의 생명주기를 연결한다. 디스크에 청크가 있거나
   화면에 보인다는 사실만으로 틱 준비가 끝났다고 판단하지 않는다. `FULL`
   결과의 소유자와 세대, 취소·재요청 및 콜백 순서를 유지한다.
2. 필요한 저장 청크와 미생성 이웃을 스트리밍·생성 작업에 연결한다. 틱 준비에
   필요한 이웃이 없으면 생성 완료를 기다리고, 월드 또는 입력이 바뀐 작업은
   반영하지 않는다. 생성 순서와 구조물·데이터팩 입력도 보존한다.
3. 실제 홀더 콜백의 실행 순서에서 저장된 후처리 작업자를 실행한다. 예약 틱뿐
   아니라 블록 변경, 조명, 블록 엔티티와 POI 등 발생한 효과를 확인하고 세션에
   반영해야 한다. 지원하지 않는 효과가 있으면 원본을 유지하고 저장을 막는다.
4. 플레이 중 저장은 후처리와 틱 작업의 완료, 저장 원본과 잠금, 플레이어와
   청크 변경을 한 경계에서 검증한 뒤 수행한다. 오류와 취소 시 세션과 월드를
   다시 사용할 수 있어야 한다.
5. 생성 화면과 실제 월드 게시·플레이를 연결하고, 여러 시드와 세 차원에서
   생성·이동·종료·재접속·저장을 검증한다. 복사한 월드를 Java 26.3과 번갈아
   열어 비교하기 전에는 전체 왕복 호환성으로 표시하지 않는다.

## 회귀 검사

`generated_world_with_extended_neighbor_saves_after_play`는 구조물이 켜진 새
월드를 생성하고 인접 청크를 확장한 뒤 플레이어를 한 틱 진행시켜 저장한다.
현재 작업 트리에서 저장된 후처리 때문에 실패한다. 설치된 26.3과 Java 25가
필요하며 디버그 빌드에서는 오래 걸릴 수 있다.

기존에 준비된 전용 테스트 월드가 있으면 복사본을
`target/region-test-temp` 아래에 두고 `RECRAFT_PLAY_SAVE_TEST_WORLD`로 지정해
`existing_generated_portal_world_saves_after_forty_ticks`를 실행할 수 있다.
이 검사는 대상 월드를 실제로 수정하므로 원본이나 사용자의 월드를 지정하지
않는다. 게임 파일과 생성된 테스트 월드는 저장소에 포함하지 않는다.
